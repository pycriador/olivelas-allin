# ServiceForge — Sprint 8
## Master Data Management (Cadastros Base)

Continuar o desenvolvimento do projeto ServiceForge.

Toda a arquitetura construída nas Sprints anteriores deverá ser preservada.

NÃO remover funcionalidades.

NÃO alterar o Core Platform.

NÃO alterar o Metadata Platform.

NÃO alterar o Event Bus.

O objetivo desta Sprint é criar todos os cadastros mestres da plataforma.

Ainda NÃO implementar Ordem de Serviço.

Todos os cadastros deverão utilizar:

• Metadata Platform

• Audit Service

• Workflow Engine

• Communication Platform

• Document Platform

• Event Bus

Todo CRUD deverá publicar eventos.

Toda alteração deverá gerar auditoria.

Toda tela deverá utilizar os componentes padronizados da plataforma.

------------------------------------------------------------------

OBJETIVO DA SPRINT

Ao finalizar esta Sprint, o ServiceForge deverá possuir um ecossistema completo de dados mestres (Master Data Management), servindo como base para o módulo de Ordem de Serviço.

Nenhuma Ordem de Serviço deverá ser criada nesta Sprint.

Todo o foco é construir um conjunto de entidades reutilizáveis, consistentes, auditáveis e integradas ao restante da plataforma.
