# ServiceForge — Sprint 10
## Ordem de Serviço — Execução Técnica

Continuar o desenvolvimento do projeto ServiceForge.

Toda arquitetura existente deverá ser preservada.

NÃO alterar:

• Core Platform
• Metadata Platform
• Document Platform
• Communication Platform
• Core Event Bus
• Workflow Engine
• Master Data

Todo o desenvolvimento deverá utilizar os serviços já existentes.

Nenhuma lógica de negócio poderá ser implementada diretamente na interface.

Toda alteração deverá publicar eventos.

Toda alteração deverá gerar auditoria.

Toda alteração deverá atualizar a Timeline.

------------------------------------------------------------------

OBJETIVO

Expandir o módulo de Ordem de Serviço.

Implementar toda a operação técnica da assistência.

Esta Sprint será responsável pelo ciclo operacional do reparo.

Ainda NÃO implementar:

• Financeiro completo

• Estoque completo

• IA

• Integrações externas

OBJETIVO DA SPRINT

Ao finalizar esta Sprint o ServiceForge deverá possuir um módulo completo de execução técnica da Ordem de Serviço, permitindo acompanhar toda a vida útil do atendimento, desde o diagnóstico até os retornos em garantia, totalmente integrado ao Core Platform, Metadata Platform, Document Platform, Communication Platform, Workflow Engine e Core Event Bus.
