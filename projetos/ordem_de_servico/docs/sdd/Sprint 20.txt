# ServiceForge — Sprint 20
## Administration Platform (Governança Global, Multiempresa, RBAC e Configuração da Plataforma)

Continuar o desenvolvimento do projeto ServiceForge.

Toda arquitetura existente deverá ser preservada.

NÃO remover funcionalidades implementadas.

Toda implementação deverá respeitar integralmente:

• Foundation Platform

• Core Platform

• Metadata Platform

• Master Data Platform

• Data Platform

• Integration Platform

• Document Platform

• Communication Platform

• AI Platform

• Workflow Engine

• Core Event Bus

Toda funcionalidade administrativa deverá ser centralizada na Administration Platform.

Nenhuma configuração global poderá ficar distribuída entre módulos.

------------------------------------------------------------------

OBJETIVO

Criar a Administration Platform.

Este módulo será responsável pela administração completa da plataforma.

Toda configuração corporativa deverá ser realizada neste módulo.

Toda configuração deverá ser Metadata Driven sempre que possível.

OBJETIVO DA SPRINT

Ao finalizar esta Sprint, o ServiceForge deverá possuir uma Administration Platform corporativa responsável por toda a governança da aplicação.

Toda administração da plataforma deverá ocorrer exclusivamente através deste módulo.

IMPORTANTE

Ainda NÃO implementar:

• Cobrança de licenças

• Marketplace online

• Provisionamento automático de empresas

• Multi-região

• Cluster distribuído

Toda a arquitetura deverá permanecer preparada para essas evoluções futuras sem necessidade de refatoração.
