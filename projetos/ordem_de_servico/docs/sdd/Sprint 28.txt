# ServiceForge — Sprint 28
## Service Order Module — Service Order Management (Abertura da Ordem de Serviço, Workspace, Timeline, Recebimento e Controle Operacional)

Continuar o desenvolvimento do projeto ServiceForge.

Toda arquitetura existente deverá ser preservada.

NÃO remover funcionalidades implementadas.

Toda implementação deverá respeitar integralmente:

• Foundation Platform

• Core Platform

• Metadata Platform

• Master Data Platform

• Data Platform

• Integration Platform

• Administration Platform

• Reporting & BI Platform

• Automation Platform

• Document Platform

• Communication Platform

• AI Platform

• Public Portal

• Workflow Engine

• Core Event Bus

• Customer Management

• Asset Management

Toda Ordem de Serviço deverá consumir exclusivamente os módulos existentes.

Nunca duplicar informações.

Nunca cadastrar Cliente ou Equipamento diretamente na OS.

Sempre utilizar os cadastros existentes.

Todos os formulários deverão utilizar Metadata Platform.

Toda auditoria deverá utilizar Audit Center.

Toda comunicação deverá utilizar Communication Platform.

Toda documentação deverá utilizar Document Platform.
