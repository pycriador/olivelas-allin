# ServiceForge — Sprint 18.5
## Data Platform (Data Connectivity, Data Sources, ETL e Governança de Dados)

Continuar o desenvolvimento do projeto ServiceForge.

NÃO alterar a arquitetura existente.

NÃO remover funcionalidades implementadas nas Sprints anteriores.

Toda implementação deverá respeitar integralmente:

• Foundation Platform

• Core Platform

• Metadata Platform

• Master Data Platform

• Document Platform

• Communication Platform

• AI Platform

• Integration Platform

• Workflow Engine

• Core Event Bus

• Administration Platform

Todo acesso a dados deverá passar pela Data Platform.

Nenhum módulo deverá acessar diretamente fontes externas de dados.

Toda comunicação deverá utilizar Providers, Connectors e Services.

------------------------------------------------------------------

OBJETIVO

Criar a Data Platform.

Este módulo será responsável por toda a conectividade, descoberta, catalogação, importação, exportação, transformação e governança de dados da plataforma.

A Data Platform será a camada oficial entre o ServiceForge e qualquer fonte de dados.

Nenhum módulo deverá implementar acesso direto a banco de dados ou arquivos externos.

OBJETIVO DA SPRINT

Ao finalizar esta Sprint, o ServiceForge deverá possuir uma Data Platform corporativa, totalmente desacoplada, responsável por toda conectividade, descoberta de esquemas, catalogação, ETL, transformação, validação, importação e exportação de dados.

A Data Platform deverá tornar-se a única camada autorizada para acesso a fontes de dados externas, garantindo padronização, segurança, auditoria, escalabilidade e reutilização por todos os módulos da plataforma.

IMPORTANTE

NÃO implementar ainda:

• Sincronização em tempo real (CDC)

• Replicação entre bancos

• Data Warehouse

• Data Lake

• Streaming de eventos

• Conectores proprietários específicos (SAP, Totvs, Salesforce, etc.)

Toda a arquitetura deverá permanecer preparada para essas evoluções futuras sem necessidade de refatoração estrutural.
